tutor · raylib · Inworld voice

Write what you mean.
The picture draws itself.

tutor reads a plain .txt file written in a small markup language. It draws the explanation with raylib, animates every change, narrates it with a realtime Inworld voice, and can read the final scene back to you in the same language.

You never write coordinates, colors, pixel sizes or easing curves. You write what exists, what each thing has, how things are connected and what changes. The engine owns a fixed dictionary from those four ideas to what the eye can see. Because of that, the picture can't contradict the model.

Quick start

terminal
make                                  # builds ./tutor and ./manim_demo (needs raylib, libcurl, ffmpeg for video)
./tutor scripts/bank.txt              # play it, narrated by Inworld
./tutor scripts/bank.txt --mute       # no voice
./tutor scripts/bank.txt --record bank.mp4   # export an mp4 with the narration muxed in
./tutor scripts/bank.txt --readback   # no window: print the final scene as markup
./tutor scripts/bank.txt --check      # no window: decodability test + axiom lint
make check                            # --check every script in scripts/

Edit the .txt while the window is open. tutor notices the save and restarts the lesson, so you can write and watch side by side.

The idea: four words in, ten channels out

Any explanation, whether a bank transfer, a derivative, a contract or a for-loop, is made of four kinds of stuff. The script answers four questions, and nothing in the answers is visual:

things

What exists? alice, bob, a function, a point, a plaintiff.

properties

What does each thing have? A number (a magnitude) like balance=100, or a word (a category) like status=overdue.

relations

How are things connected? cause, maps-to, part-of, equals, similar, order.

change

What is different a moment later? balance 100 → 70, h shrinks toward 0, owes → paid.

The engine maps those words onto the visual channels through one fixed dictionary:

model wordchannelwhat you see
thinga marka dot, bar, box, line or curve with a stable identity
magnitudesizebar length or dot area, measured from a shared zero
categorycolor / shapesame category, same color; things with no category each get their own
orderpositionleft to right in the order you declared them, or along the schema's axis
part-ofenclosurea box drawn around the parts
cause / connectedconnectionan arrow / a line between marks
equals / similaroverlapa dashed link marked = or ≈
name, exact valuetexta short label; the voice carries the sentences
changemotionthe mark morphs smoothly; it is never replaced
what the voice is aboutfocusone thing lit, everything else dimmed

The six axioms, enforced for you

axiomrulehow the engine keeps it
1 · Identityone thing, one mark, for its whole lifeThere is no delete verb. Re-marking an id updates it in place, and a morph with a wrong from animates from the true value and warns.
2 · StructureA > B in the model means mark A is visibly bigger, by the right ratioBars share one zero line. Each property gets one scale, fixed by pre-scanning every value the script ever uses, so it never jumps.
3 · Zerono relation in the model means no relation on screenUnrelated things never share a color. Accidental overlaps are pushed apart or reported.
4 · Continuitychange is continuous motion, cause before effectEvery change eases. New marks grow in, links draw themselves, and focus fades.
5 · Bounded focusone subject at a timefocus lights one thing and dims the rest to 20%.
6 · Decodabilitysomeone who knows the dictionary can rebuild the model from the picture--readback prints the scene, and --check proves it re-parses to the same scene.

Your first script

Here is the whole bank-transfer lesson. Read it top to bottom; each line is one statement.

scripts/bank.txt
# How a bank transfer works: the example from the spec.
title "How a bank transfer works"

mark alice bar account balance=100 label="Alice" unit=$
mark bob   bar account balance=20  label="Bob"   unit=$

Say: "Alice has a hundred dollars. Bob has twenty."
focus alice
Say: "Alice sends Bob thirty |go|."
@go link pay arrow alice -> bob amount=30
@go morph alice.balance 100 -> 70 1.5s
with morph bob.balance 20 -> 50 1.5s

focus bob
Say: "Now Alice has seventy and Bob has fifty."
focus none
Say: "Nothing was created or destroyed. Thirty dollars just moved."
  1. title sets the small heading. It is setup, not model.
  2. mark alice bar account balance=100 … declares a thing called alice, drawn as a bar, of category account, with a magnitude balance. label is its display name, and unit=$ prefixes values.
  3. Because Alice and Bob share the category account, they share a color. Because both have balance, they share one scale on one zero line, so 100 really looks five times 20.
  4. Say: speaks a line. The next statement waits until it has been said.
  5. focus alice lights Alice and dims everything else.
  6. |go| inside the sentence is a hook. The lines that start with @go wait for the voice to reach that point.
  7. with attaches a line to the one before it so they run together: one bar goes down while the other goes up.

Swap the words, keep the structure, and the same engine explains law:

scripts/law.txt
# Swap the words, keep the structure: the same engine explains law.
title "A breach of contract"

mark plaintiff party obligations=2
mark defendant party obligations=0
Say: "Two parties. The plaintiff carries two obligations, the defendant none."

link suit arrow plaintiff -> defendant claim="breach"
focus suit
Say: "The plaintiff sues for breach of contract."

focus defendant
Say: "If the court agrees, |rule| the defendant takes on an obligation."
@rule morph defendant.obligations 0 -> 1 2s
focus none

How a script runs

A script is a list of steps, run top to bottom. Some steps happen instantly and the next one starts right away. Others take time, and the next step waits for them.

statementtimingnotes
mark link group focus schema titleinstantTheir entrance animations (grow in, draw on, fade) run in the background.
morphblocksfor its duration (default 1 s)
Say:blocksuntil the line has been spoken
wait 1sblocksfor the time given
pauseblocksuntil the viewer presses space or →
scene "…"blocks0.7 s fade-out, then a fresh stage

Two modifiers change when a line runs:

  • with joins a line to the step before it, so they start together. Chain as many as you like.
  • @name takes a line out of the sequence. It waits until the voice reaches |name| in any Say, then runs, once. A with line right after an @name line belongs to the same hook.

Hook markers: silent or glued

you writefires
"…thirty |go|."Silent marker: fires where it sits, here right after "thirty" finishes. Trailing punctuation is shown on the previous word.
"…sends |go| Bob thirty."Mid-sentence: fires as "Bob" begins.
"…sends Bob thirty|go|."Glued to a word: fires the moment "thirty" is spoken.
"|a| one |b| two"Any number of markers per line. Each name fires once, the first time it is reached.
Timing comes from the voice itselfWith Inworld on, hooks fire on Inworld's own word timestamps, and the line's clock is the audio position, so a hook lands exactly on the word you hear. When muted, timing is estimated from word length and punctuation.

The verbs

Six verbs make the model. A handful of setup lines control the stage. A line starting with # or // is a comment, as is anything after a # that follows whitespace. Lines starting with ``` are ignored, so you can paste a markdown code block straight in.

marka thing and its properties
mark <id> [kind] [category] key=value …

Declares a thing. kind is one of the eight mark kinds; leave it out and the schema picks one. A bare word that isn't a kind is the category (one per mark). Everything else is key=value.

mark alice bar account balance=100 label="Alice" unit=$
mark f path fn={x^2} label="f(x) = x²"
mark eve dot student score=72
mark h label value=1 label="h"

Re-marking an existing id updates it instead of erroring. Changed numbers ease to their new value over 0.7 s, changed words cross-fade, and new properties are added. An AI that loses track of state can't break the scene.

linka relation between two things
link [id] [kind] <a> -> <b> key=value … (directed) link [id] [kind] <a> -- <b> key=value … (undirected)

Kinds: arrow (also cause, maps-to), line (also connected), similar (dashed, ≈), equals (dashed, =). With no kind, -> gives an arrow and -- a line. The id is optional (default a->b), but give one if you want to focus or morph the link later.

Endpoints can be marks or groups. The link's properties become its label: label="…" verbatim, otherwise the values (claim="breach" shows breach, amount=30 shows amount 30). bend=40 curves it. Two links running in opposite directions bend apart on their own.

link pay arrow alice -> bob amount=30
link suit arrow plaintiff -> defendant claim="breach"
link close similar q -- p
link c1 arrow main -> f3 label="calls"
grouppart-of: an enclosure around parts
group <id> part-of=[a,b,…] [label="…"] [color=…]

Draws a box around its members and keeps them together in the layout. Members can be marks or other groups (nesting works), and a group can be the end of a link. members=, parts=, [a,b] or plain words after the id also work.

group state part-of=[i,n] label="loop condition: i < n"
group outer part-of=[inner,c] label="outer"
morphchange: the only way anything moves
morph <id>.<prop> [from] -> <to> [1.5s | 500ms] [ease=name]

Animates one property. Since the engine owns the dictionary, a balance change is a height change, an x change is a move, and a to change on a region is its edge sliding. from is optional and is a promise: if it doesn't match the real value, the engine animates from the real value and warns (no jump cuts).

  • numbers interpolate with the ease you choose (default smooth)
  • words (categories) cross-fade the label, and the color morphs to the new category's color
  • expressions: -> {a.balance * 2} animates to the value, then the property stays bound to the expression
  • works on links and groups too, e.g. morph pay.label "pending" -> "sent"
  • a newer morph of the same property takes over from a running one
  • morphing a property that doesn't exist yet creates it

Eases: smooth · linear · in (rush_into) · out (rush_from) · slow_into · double_smooth · there_and_back · cubic · back (overshoot) · wiggle.

morph alice.balance 100 -> 70 1.5s
with morph bob.balance 20 -> 50 1.5s
morph h.value 1 -> 0.01 4s ease=smooth
morph delivery.status pending -> breached 1.5s
morph area.to 0.2 -> 3 4s ease=linear
focuswhat the voice is about
focus <id> | none

Lights one mark, link or group and fades everything else to 20%. Focusing a group lights its members, and regions and lines that are of= a focused path stay at 70%. focus none (or all) brings everything back. Exactly one subject at a time: that is axiom 5.

Saythe voice, with hook markers
Say: "text with |hook| markers"

Speaks and subtitles a line, word by word. Quotes are optional, and “smart quotes” work. Markers are covered in How a script runs. The subtitle highlights the current word and underlines words that fired a hook.

How a property is read

  • Magnitude: the first numeric property that isn't a positional key. It drives size (bar length, dot area) and the number shown, and it is what a bare id means in an expression ({h} is h's magnitude).
  • Category: the bare word after the kind (mark alice bar account …) or, if there is none, the first text property that isn't a text key (status=pending). It drives color.
  • Everything else is shown as text where the kind has room (boxes list all their properties).

Expressions

Wrap a value in braces and it becomes live: it is re-evaluated every frame, so when something it depends on morphs, it moves too. This is how a secant follows a shrinking h and a mean slides when one score drops.

mark h   label value=1 label="h"
mark q   dot x={1+h} y={f(1+h)} label="Q"
mark m   label value={(f(1+h) - f(1)) / h} label="secant slope"
mark avg label score={mean(score)} label="mean"
mark A   label value={integral(f, 0, area.to)} label="area so far"

If an expression can't be computed (division by zero, a cycle like z={z+1}, or an unknown name), the readback shows nan/inf and a value: lint names the culprit.

Schemas (layouts)

Each schema owns its layout rules, so position always means something. If you don't write a schema line, tutor infers one per scene: paths, regions or x= give axes; t= gives timeline; links between things with no magnitudes give graph; anything else is free. numberline is never inferred; ask for it.

free default

Things stand left to right in the order you declared them, each group keeps its members together inside an enclosure, and bars stand on one shared zero line. Each magnitude property has its own scale, and a new property starts its own baseline segment after a gap, so a fee never borrows the balance scale. With negative values the zero line rises to make room below. Linked neighbours get spaced apart so the link's label fits; links between bars arc over the top.

numberline

schema numberline prop=score range=[0,100] zero=true

One magnitude becomes horizontal position. prop= picks it (default: the most common magnitude), range= fixes the ends (default: a padded range around every value the script uses), and zero=true forces 0 into view. Equal values stack upward instead of hiding each other, and name labels lift to avoid collisions. A label mark that has the property becomes a pointer under the line, which is good for means, medians and thresholds. Things without the property line up in the top band.

axes

schema axes x=[-0.5,3] y=[-1,9] zero=false

Two magnitudes become x and y. Ranges default to fit every point, line end, region edge and path sample (outliers are trimmed to 2–98%). Zero is kept in view unless zero=false. On axes:

  • dot with x= y= is a point; morph x or y to move it
  • path fn={…} draws itself on, with domain=[a,b] to limit it
  • path xt={…} yt={…} range=[t0,t1] is a parametric curve (orbits, circles, cycloids)
  • region of=f from=a to=b fills under a path; morph to to sweep it
  • line x1 y1 x2 y2 [extend=1] or line x y slope (a tangent through a point)
  • arrow x1 y1 x2 y2 is a vector
  • bar x= y= [w=] is a histogram or Riemann bar
  • label x= y= is text at a point; labels without a position stack inside the plot at top left

timeline

schema timeline range=[0,60]

Order in time becomes x. Marks with t= (or at=, year=) are events on the line, with labels alternating above and below on leader lines. Things without a time (the parties, the people) stand in a row above. Use a text property like status= as the category so a change of state is a change of color.

graph

Things and connections, with no axes. If the links form no cycle, the layout is layered left to right (call stacks, org charts, pipelines). Otherwise it is force-directed, with groups pulling their members together, the drawing centred, and overlapping nodes pushed apart. Things default to boxes, or dots if they have a shape.

Color, shape, focus

  • Color is never decoration. Each category value gets one palette slot, and each uncategorized thing gets its own. So: same color = same kind, different color = unrelated. There are 10 well-separated hues; an 11th kind triggers a warning because colors would repeat.
  • Regions and lines that are of= a path take that path's color, since they are part of it.
  • Morphing a category (status pending → breached) morphs the color too, so a change of state is visible at a glance.
  • Shape is the second categorical channel, for dots: circle square triangle diamond star hexagon ring. Use it when color is already carrying another meaning, or for print.
  • Focus is the voice's pointer. Move it with every new subject in your narration. Lines that focus on nothing (focus none) work best at the start and end.
  • A thing appears by growing in. Links draw from source to target. A change of focus fades over about 0.3 s.

Scenes & hand placement

scene: start a fresh stage

Identity forbids deleting a thing mid-explanation, but a lesson can have chapters. scene "Part two" fades the whole stage out in 0.7 s, then starts clean: no marks, focus, colors or schema. Its text becomes the title. Each scene infers its own schema.

title "Orbits"
schema axes x=[-2.5,2.5] y=[-1.6,1.6]
…
scene "Who owes whom"
schema graph
…

pos: put a thing exactly here

pos=[fx,fy] places a mark at a fraction of the stage (0,0 top-left; 1,1 bottom-right) in any schema, and it is left out of automatic layout. Use it for diagrams whose spatial arrangement is the point (a cycle, a map, cause and effect left to right). It is the only coordinate the language allows, and it is a fraction, never pixels.

mark rain   box weather mm=30     pos=[0.15,0.45]
mark ground box soil    wetness=0 pos=[0.5,0.45]
mark crop   box plant   height=10 pos=[0.85,0.45]
link r1 arrow rain -> ground label="soaks"

Voice (Inworld)

Narration uses Inworld's streaming TTS. Everything is automatic once a key is found (--inworld-key, then $INWORLD_API_KEY, then a file ./.inworld_key).

  1. Prefetch. At load, every Say line is queued in script order to three workers. The first line usually speaks within half a second, and later lines are fetched while earlier ones play.
  2. Stream. Audio arrives as raw 16-bit PCM over NDJSON and plays through a raylib audio stream as it arrives, so a long line starts before it has finished synthesising.
  3. Sync. Inworld sends word timestamps with the audio, and hooks fire on them. While a line plays, its clock is the audio position, so pausing, stutters and network gaps can't put the picture out of sync with the voice.
  4. Cache. Finished lines are saved in .tutor_cache/ (PCM, word timings, WAV). Re-runs and hot-reloads are instant and cost nothing. Edit a line and only that line is fetched again.
  5. Record. With --record, video time drives the clock (never ahead of the audio), and each line's WAV is muxed into the mp4 at the moment it was spoken.

Writing for the ear

  • Spell numbers the way they should be said: "seventy one", "two point five". Inworld normalises digits, but words give you control, and hooks align more reliably.
  • Keep lines to one idea, about 8 to 20 words. Each Say is a separate request, so short lines start faster.
  • Punctuation is pacing: a comma is a breath, a period is a pause.
  • If Inworld fails or takes more than 10 s, that line falls back to estimated timing with a voice: warning, and the lesson carries on.

Readback, check & lint

Readback is the scene described in the same vocabulary you wrote it in. It is how an AI (or you) can carry on a conversation about what's on screen without screenshots or coordinates.

./tutor scripts/bank.txt --readback
# readback t=0s
title "How a bank transfer works"
# schema (auto) free
mark alice bar account balance=70 label=Alice unit=$
mark bob bar account balance=50 label=Bob unit=$
link pay arrow alice -> bob amount=30
# derived balance: max=alice min=bob mean=60 total=120 order: alice > bob
# since: morph alice.balance 100 -> 70 done; morph bob.balance 20 -> 50 done
  • Plain lines are valid markup: the current model.
  • # value: gives the current result of every expression.
  • # derived gives max, min, mean, total and order for each magnitude shared by two or more things.
  • # overlapping: lists pairs whose marks coincide on screen.
  • # since: lists the changes that have finished, most recent last.
  • # lint: lists everything the engine had to correct or warn about.

--check is the decodability test (axiom 6). It runs the script, writes the final scene back as markup, parses that into a fresh engine, and confirms it rebuilds the same scene. It exits 1 if they differ, if the script has parse errors, or if any identity or Zero warning fired. make check runs it on every script.

Playground

Write or paste a script. This page highlights it and runs the same structural checks as the parser: verbs, kinds, key=value, link arrows, morph targets, hooks and references. Then copy it into a .txt and run it.

Writing good explanations

  1. Answer the four questions before writing anything. List the things, their properties, the relations, and what changes. If a property doesn't change and doesn't matter, leave it out.
  2. Declare first, then narrate. Put the marks that exist from the start at the top; they grow in together. Introduce later things with @hooks as the voice names them.
  3. Hook the word that names the change. "…sends Bob thirty|go|" beats a hook at the start of the sentence. The motion should land as the viewer hears the reason for it.
  4. One focus per sentence. Before each Say, ask what the sentence is about and focus it.
  5. Change values, not pictures. If you want something to look different, find the property that differs in the model and morph it. If there isn't one, the visual change would be decoration (axiom 3).
  6. Duration is about understanding. Give a morph as long as the idea needs: 1.5 to 4 s for the main change, 0.6 to 1 s for bookkeeping. ease=linear suits sweeps and steady processes; the default smooth suits transitions.
  7. Same property name, same scale. Name properties so things that should be compared share a name (balance for both accounts), and things that shouldn't, don't (fee).
  8. Use categories deliberately. Things of the same kind share a category word, and a state that changes is a text property you can morph.
  9. Prefer expressions over repeated morphs. If B depends on A, write B as {…A…} and morph only A.
  10. End by running --check, and read the readback as if you had never seen the script. If you couldn't recover the story from it, neither can a viewer.

# Calculus: the derivative as the limit of secant slopes.
title "The derivative is a limit"
schema axes x=[-0.5,3] y=[-1,9]

mark f   path fn={x^2} label="f(x) = x²"
mark h   label value=1 label="h"
mark m   label value={(f(1+h) - f(1)) / h} label="secant slope"
mark p   dot x=1 y={f(1)} label="P"
mark q   dot x={1+h} y={f(1+h)} label="Q"
mark sec line x1=1 y1={f(1)} x2={1+h} y2={f(1+h)} extend=1 label="secant"

Say: "Take two points on the curve, P and Q, a distance h apart."
focus sec
Say: "The line through them is a secant. Its slope is three."
focus q
Say: "Now let h shrink toward zero, |shrink| and watch Q slide down to P."
@shrink morph h.value 1 -> 0.01 4s ease=smooth
@shrink link close similar q -- p
focus m
Say: "The secant slope settles at two."
mark tan line x=1 y={f(1)} slope={deriv(f, 1)} label="tangent"
focus tan
Say: "That limiting line is the tangent. Its slope, two, is the derivative of x squared at one."
focus none

struct Demo : rm::Scene {
  void construct() override {
    auto shape = rm::Circle({640, 380}, 110, rm::col::blue);
    play(rm::Create(shape));
    auto square = rm::Square({640, 380}, 200, rm::col::orange);
    play(rm::Transform(shape, square));        // raylib has its own Transform: qualify it

    auto k = rm::Tracker(1);
    auto graph = rm::FunctionGraph(ax, [](double x) { return std::sin(x); }, -4, 4);
    graph->addUpdater([ax, k](rm::Mobject &m, float) {
      m.paths = {ax.plot([&](double x) { return std::sin(k->value * x); }, -4, 4)};
    });
    play(rm::Create(graph, 2));
    play(rm::ChangeValue(k, 3, 3));            // the curve re-draws itself every frame
  }
};

Troubleshooting

Nothing moves after a Say

The lines are probably tagged @name, but the sentence has no |name|. Look for a hook: lint in the terminal, or run with --verbose to see each hook fire.

A bar looks too small or too big

Scales are per property name and fixed by the largest value the script ever uses. A bar at 20 next to a bar that later reaches 1000 will look small from the start. That is axiom 2 working. Use a different property name if they shouldn't be compared.

Two things have the same color and they shouldn't

They share a category word, or a text property such as status= with the same value. Same category means same color, so give them different categories.

The voice is silent

The terminal shows voice: inworld <id>, N lines (…) when it is on. If you see a voice: warning instead, check the key file and the network. --mute turns it off on purpose.

I want to remove something

There is no delete: a thing keeps its identity for the whole scene. Morph it to zero, focus something else, or start a new scene.

My expression shows nan

Read the value: lint. Common causes are a path id typo inside f(…), dividing by a value that reaches 0 (morph h to 0.01, not 0), or a mark referring to itself.
