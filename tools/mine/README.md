# Mining 3Blue1Brown into visual moves

`chat/idioms.md` is a library of *visual moves* (highlight a part, count one by one, slide a window, transform a
formula…). Each one is written in the tutor's markup on a small example, mined from the step comments 3Blue1Brown
writes above his animation code. This folder rebuilds it.

```
sh tools/mine/fetch.sh                                         # 3b1b/videos at the pinned commit -> work/videos
python3 -I tools/mine/extract.py tools/mine/work tools/mine/work/blocks.jsonl
node tools/mine/mine.mjs taxonomy                              # proposal -> work/taxonomy-proposed.json (hand-edited into taxonomy.json)
node tools/mine/mine.mjs label                                 # Sonnet labels every usable block
node tools/mine/mine.mjs label --model opus --out labels-opus.jsonl   # a second, independent labeller
node tools/mine/mine.mjs audit --model opus --n 400            # agreement, Cohen's kappa
node tools/mine/mine.mjs select                                # varied candidates per kind, from the agreed labels
node tools/mine/mine.mjs translate                             # -> markup, engine check, up to 2 repair rounds
node tools/mine/mine.mjs judge                                 # frames per sentence, a vision judge, pass/fail
node tools/mine/mine.mjs assemble                              # -> chat/idioms.md, chat/idioms/*.txt, idioms.jsonl
```

`work/` is not committed: it holds the 3b1b clone, the model-call cache and the frames. Every model call is cached by
a hash of its input, so rerunning a stage repeats it exactly and costs nothing.

## Datasheet

**Source.** github.com/3b1b/videos at commit 306a134 (2026-09-29): 3Blue1Brown's manimgl scene code, 2015–2026.
Used for personal use.

**Unit.** A *block*: a prose comment inside a scene method plus the code under it, up to the next comment (at most
40 lines). It records its animation calls, the scene's base classes and its provenance (`file:line`).
There are 6,108 blocks.

**Filtering.** Kept (3,156 blocks): from 2019 on (the current manimgl API), at least one `play()`, and none of these flags:
- `3d`: ThreeDScene, surfaces, camera orientation;
- `pi`: Pi creatures, teacher/students;
- `image`: images and SVGs;
- `loop`: objects generated by loops.

Our markup has no counterpart for any of these (measured in `research_notes/Mining 3Blue1Brown/translation.md`).

**Kinds.** `taxonomy.json`: 34 kinds of visual move, 32 of them usable plus `setup` and `other`.
- Claude proposed taxonomies from two random samples of 300 comments, then merged them. That proposal is kept in work/taxonomy-proposed.json.
- It was hand-edited: near-duplicates merged, non-visual moves folded into `other`, "reveal one by one" added.
- The definitions of the most-confused pairs were sharpened after the first audit (v2).

**Labels.**
- Sonnet and Opus each label every block independently, with the comment, its animation calls and the first lines of its code.
- Agreement on a random 400:
  - v1 (comment and calls only): 61.5%, κ 0.60;
  - v2 (sharpened definitions, plus code): 64.5%, κ 0.63.
- This is below the usual 0.7, mostly because many blocks do two moves at once (write a formula, then highlight it) and a single label must pick one.
- So only blocks both labellers agree on (2,186, 69%) are used. Per-kind agreement is in work/audit.json.
- No human labels yet. The user's review of the final idioms is the human check.

**Selection.**
- Per kind, the most typical block (the medoid by code-token similarity) first.
- Then each next pick is the one least like those already picked (k-center).
- One per video, no near-duplicates (Jaccard ≥ 0.8), comments of at least 3 words, 3–30 lines of code.
- Up to 6 per kind: 184 candidates.

**Translation.**
- Sonnet writes each as a self-contained idiom under the engine's axioms (system prompt: the language reference, the dictionary and axioms, and the gold exemplars).
- `tutor --check` must report it decodable, with no lint of any kind other than layout notes and no retired placement words.
- Up to two repair rounds feed the engine's messages back. "NOT EXPRESSIBLE" answers are recorded, not forced.

**Judging.**
- Frames at the end of every sentence.
- A Claude vision judge answers four pass/fail questions: faithful to the move, legible, shown (what's said is on stage), reusable. Only all-pass idioms are kept.
- The judge's verdicts are spot-checked by hand against the frames (see the report). Idioms rejected on review are listed in `work/rejected.txt`.

**Assembly.**
- Per kind, up to 2 passing idioms, from different videos, shortest first; at most 50 in all.
- Each carries its source `file:line` and 3Blue1Brown's comment in `idioms.jsonl` and as a comment in `chat/idioms.md`.

**Known limits.**
- The labels come from models, not people.
- The judge is a model too.
- 3Blue1Brown's style is one person's.
- Moves that need 3D, characters, images or generated sets aren't here.
- The idioms are small examples: they teach a pattern, not a topic.
